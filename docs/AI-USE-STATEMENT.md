# AI-use statement

**Date:** 4 August 2026  
**Applies to:** TSDNE source, documentation, related-work research, and future publications

## 1. Disclosure

Generative AI systems have been used extensively in the development of this repository. Their roles have included:

- drafting and restructuring Markdown documentation;
- proposing code and tests;
- locating possible related work;
- producing bibliographic leads;
- adversarially criticising claims and implementation choices;
- comparing repository statements with source code;
- editing prose for clarity and consistency.

The repository should not imply that every sentence, architectural choice, citation, or line of code was produced without machine assistance.

## 2. Human responsibility

Tomas Laurenzo remains responsible for:

- the artistic proposition;
- decisions about what the work does and refuses;
- acceptance or rejection of code changes;
- final authorship and voice;
- factual accuracy;
- citation accuracy and interpretation;
- compliance with venue, journal, institutional, and funding policies;
- disclosure of AI use in any submission;
- consequences for collaborators and co-authors.

A model’s fluency, confidence, or ability to produce a plausible source description is not evidence that the source was read or understood.

## 3. Source-verification states

Every source considered for publication should carry one of the following internal states:

1. **Lead only** — discovered through search, a model, a bibliography, or a secondary reference.
2. **Canonical record checked** — publisher, proceedings, artist, institutional, repository, or standards metadata inspected.
3. **Relevant passage checked** — the passage or project behaviour supporting the claim inspected directly.
4. **Full source read** — the complete cited work read by the author responsible for the manuscript.
5. **Ready for submission** — bibliographic record, quotation, paraphrase, context, and claim boundary checked in the manuscript.

“Verified” must not be used as a synonym for “a model found a plausible matching page.”

## 4. Code-verification states

Machine-proposed code is not considered complete when it merely parses or passes unit tests. It requires, as applicable:

- source review;
- deterministic tests;
- integration tests;
- real-browser execution;
- GPU execution;
- representative-device testing;
- accessibility review;
- security and dependency review;
- aesthetic inspection;
- comparison between documentation and implementation.

For an artwork, visual and experiential judgement cannot be delegated to syntax checks.

## 5. Prohibited uses of machine authority

The project must not:

- cite a model-generated audit as independent validation;
- describe search snippets as a literature review;
- mark a bibliographic correction closed without inspecting the canonical record;
- attribute an authored fallback to a model;
- infer visitor preference, attachment, or meaning from dwell time alone;
- manufacture claims of novelty through an arbitrarily long conjunction of properties;
- preserve machine-generated prose merely because it sounds scholarly;
- use an AI-use disclosure to transfer responsibility away from the author.

## 6. Publication disclosure

Each submission must follow the receiving venue’s current policy. A suitable baseline disclosure is:

> Generative AI systems were used during exploratory research, code prototyping, adversarial review, and editorial restructuring. The author reviewed the submitted argument, code claims, and cited sources and remains responsible for their accuracy. AI systems are not listed as authors.

This wording must be amended if a venue requires model names, dates, prompts, affected sections, or a more detailed account.

## 7. Voice

Repository documents are working records, not final publication prose. Before submission:

- rewrite the argument in the author’s own voice;
- remove repetitive symmetrical structures and generic “not X but Y” constructions where they do not perform necessary reasoning;
- replace premature declarations of agreement or completion with evidence;
- preserve uncertainty where the project has not yet produced an answer;
- distinguish an artist’s proposition from a model’s retrospective rationalisation.

## 8. Collaborators

Machine assistance must not alter:

- author order;
- contribution descriptions;
- quotations;
- collaborator status;
- consent;
- attribution;
- ownership or licensing representations.

All such details require direct human confirmation.

---

This document is a disclosure and accountability protocol. It is not a claim that machine assistance has already been reviewed exhaustively or that every repository source is ready for publication.
